# Arihant Workspace - API Documentation

> Source: architecture review approved on 2026-11-06. Update this document as the implementation evolves.

## 10. API endpoint breakdown (`/api/v1`)

- **auth:** POST `login`, `refresh`, `logout`, `logout-all`, `forgot-password`, `reset-password`; GET `me`; PATCH `me/password`
- **users:** CRUD, `/:id/status`, `/:id/roles`, `/:id/skills`, `/:id/workload`, `/:id/passport`, `/:id/availability` (CRUD and approve)
- **departments, roles, permissions (read), skills, holidays, settings:** CRUD
- **projects:** CRUD, `/:id/archive`, `/:id/duplicate`, `/:id/members`, `/:id/health`, `/:id/progress`, `/:id/overview` (360° aggregate), `/:id/versions`, `/:id/activity`, `templates` CRUD
- **milestones, sprints, epics:** nested `projects/:id/...` CRUD
- **tasks:** CRUD, `bulk` (PATCH), `/:id/status`, `/:id/assign`, `/:id/watchers`, `/:id/checklist`, `/:id/dependencies`, `/:id/subtasks`, `/:id/activity`, `/:id/close-request`; GET `tasks?view=board|list|calendar|timeline` with shared filter params; `saved-views` CRUD
- **comments, attachments:** polymorphic `/:entityType/:entityId/comments|attachments`; `attachments/:id/download` (signed URL)
- **assignment:** POST `suggest` (single task, top-N with breakdown), `preview` (batch, returns plan), `plans/:id/approve|reject|modify`, `reassign/preview` (user unavailable), `rebalance/preview`; GET `history`, `workload` (team); GET/PUT `config` (weights, caps)
- **worklogs:** CRUD, `timer/start|pause|resume|stop`, `timer/current`; **timesheets:** GET mine/team, POST `/:id/submit|approve|reject`; **journals:** CRUD
- **dashboard:** `executive`, `my`, `snapshot?from&to` (+ `export?format=pdf|xlsx`)
- **analytics:** `/projects|employees|departments|tasks|hours|delivery|risks|utilization|assignment` with common filters; `ask` (NL query); `reports` saved views and exports
- **meetings:** CRUD, `/:id/minutes`, `/:id/action-items/:itemId/convert`
- **documents:** CRUD, `/:id/versions` (upload), `/:id/download`, `/:id/publish` (approval)
- **risks:** CRUD, `/:id/escalate`, `heatmap`, `early-warnings`
- **approvals:** GET inbox/outbox, POST `/:id/approve|reject|delegate`; `workflows` CRUD
- **releases:** CRUD, `/:id/deploy`, `/:id/rollback`, `/:id/approve`
- **stakeholders, change-requests, feedback:** CRUD; `portal/*` (stakeholder-scoped read and feedback)
- **notifications:** list, `/:id/read`, `read-all`, `preferences`
- **automations:** rules CRUD, `/:id/enable|disable|test`, `runs`
- **ai:** `requirements-to-tasks`, `project-summary`, `summarize-document`, `worklog-draft`, `duplicates`, `explain-health`, `risk-scan`, `report`, `mom-to-actions`, `chat` — all **return proposals**; applying them goes through normal endpoints after user confirmation
- **admin:** `audit-logs`, `login-history`, `exports`, `system/health`
- Global search: GET `search?q=` (projects, tasks, documents, users; permission-filtered)

## Conventions

- Base path: `/api/v1`. Interactive docs at `/api/docs`; raw spec at `/api/openapi.json`. Both are disabled in production.
- Success: `{ "success": true, "data": ..., "meta"?: { page, limit, total, totalPages } }`
- Error: `{ "success": false, "error": { code, message, details?, requestId } }`. Codes: `BAD_REQUEST`, `VALIDATION_ERROR`, `UNAUTHENTICATED`, `FORBIDDEN`, `NOT_FOUND`, `CONFLICT`, `UNPROCESSABLE`, `RATE_LIMITED`, `INTERNAL_ERROR`, `SERVICE_UNAVAILABLE`.
- Every response carries an `X-Request-Id` header. Quote it when reporting issues.
- List endpoints accept `page` (default 1), `limit` (default 20, maximum 100), `sort` (`field` or `-field`, from a per-endpoint allow-list) and `q`.

### Phase 5A endpoints (analytics, health, risks, reports)

All analytics accept `from`, `to` (YYYY-MM-DD, default last 30 days), `departmentId` and `projectId`. Results are limited to the caller's scope: organisation, department, the projects they take part in, or (own scope) only their own tasks and hours.

| ---------------- | ------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| GET              | `/analytics/activity`           | `analytics:view`                                              | Latest activity across projects in scope.                                                                                                                    |
| GET              | `/analytics/health`             | `analytics:view`                                              | Health score, band, factors, progress and early warnings for every open project in scope.                                                                    |
| GET              | `/analytics/projects/:id`       | `analytics:view` and project visible                          | Burndown, 12-week throughput, cumulative flow, on-time delivery, average cycle time, health.                                                                 |
| GET              | `/analytics/hours?groupBy=`     | `analytics:view`                                              | `project`, `user`, `category` or `week`: hours and entry counts per group.                                                                                   |
| GET              | `/reports/snapshot?format=`     | `analytics:view`                                              | Management snapshot as `json`, `pdf` or `xlsx`; file formats are audited.                                                                                    |

| GET/POST         | `/risks`                        | `risk:read` / `risk:write`                                    | List (`projectId`, `type`, `status` incl. `active`, `severity`, `ownerId`) or raise. Severity from probability x impact (16+ critical, 10+ high, 5+ medium). |
