## Known issues / follow-ups

- Phase 5A pages have not been checked in a real browser by an automated tool; please review the dashboard, Analytics, Project Health and Risks pages in light and dark mode.
- Cumulative flow needs at least two nightly snapshots before it draws.
- The burndown is reconstructed from task creation and completion dates.
- A new occurrence of a repeating task is not linked to a milestone (milestones are usually one-off dates).
- Templates are edited by saving a project again or through the API; there is no in-app task-by-task template editor yet.
- The AI assistant has not been exercised against the real Claude API: no `ANTHROPIC_API_KEY` is configured in this environment. Set it on the API server and enable the assistant in System Settings to use it.
- Ask Your Data covers tasks, hours, project health, risks and workload; other questions are answered with "not supported". Forecasts use estimated effort (unestimated tasks count as 1 h) and need a few weeks of completed work to be meaningful.
- Automations run inside the API / worker process that raised the event (with per-action error capture), not through a retrying queue.
- The rule editor offers notification targets by role; notifying named people is available through the API.
- Notifications raised by the background worker (due-date and approval reminders, executed plans) appear on the next poll (within 60 s) rather than instantly.
- In the DEV seed data, departments may have no head; department-head approval stages are then skipped (shown as "Skipped" in the request).
- The workflow editor offers project manager, department head, reporting manager and role stages; "named people" stages are available through the API.
- External stakeholders see shared, published documents through the normal API; a dedicated stakeholder portal (sign-off, feedback forms) is future scope.
- Tasks are linked to a release through the API only (`taskIds`); the release form has no task picker yet.
- Required custom fields apply to tasks created by people; tasks created from templates or repeat rules are not blocked by them.

- Pages have not yet been checked in a real browser by automated tests (Playwright E2E is scheduled for Phase 8); manual UI review is needed.
- The board shows up to 200 cards per column (with a note); the calendar and timeline show up to 100 tasks per range. Use filters or the list view for more.
- Uploads pass through the API (25 MB). If the Vercel proxy limits request bodies in production, switch to pre-signed direct uploads.
- Live smoke tests left synthetic DEV projects ("DEV Smoke Project", "DEV Regression Sprint") in the development database.
- Notifications for assignment, approval and reminders inside the app arrive with the Notifications module (Phase 6); reminders are e-mailed today.
- Permissions are read from MongoDB on every request (two indexed reads). Add a short Redis cache if profiling shows a need.
